## 📄 Notes on the Source Extraction
- **Page markers:** Each `<!-- Page N -->` marker is the **physical PDF page number** (the content that follows the marker is that page's content), matching the convention used in `../clean-code/` and `../growing-oo-software/`. The book's own printed page numbers (used inside the catalog cross-references, e.g. *Extract Function (106)*) differ from these physical page numbers.
- **This is a "reading order" ebook export.** It contains the title/copyright pages and the twelve chapters only — there is **no separate table of contents, preface, foreword, bibliography, or back-of-book index** in the PDF. PDF pages 1, 454, and 455 are scanned/image-only (cover art) and carry no extractable text.
- **Reader-chrome de-noising:** The PDF was captured from an online reader whose left navigation sidebar (`History`, `Topics`, `Tutorials`, `Offers & Deals`, `Highlights`, `Settings`, `Support`, `Sign Out`, `Playlists`) bled, character-by-character, into the first lines of each **chapter-opening page** (physical pages 2, 3, 5, 56, 85, 100, 118, 121, 183, 224, 268, 289, 342, 389). These 14 pages were de-interleaved and the chapter-intro paragraphs/refactoring cross-references were reconstructed and verified.
- **Garbled catalog code rebuilt:** The catalog's *Mechanics* and *Example* sections use a layout that the extractor's table detector mis-read as garbled Markdown tables (scrambling code across cells and, in a few cases, swallowing whole pages). The 36 affected pages were **rebuilt from positioned text items** (`pdf2md --items-json`), sorting by reading order and re-fencing code, headings, and italic refactoring names. All 53 mis-detected "tables" were verified to be code — this book contains **no genuine data tables** — so every one was converted back to fenced code / prose. The Safari/O'Reilly "Click here to view code image" link captions (697 of them) were removed.
- **⚠️ Known limitation — the hyphen-minus glyph (`-`) is dropped:** In this PDF's fonts the ASCII hyphen-minus is not decoded, so **every `-` is missing** from the extracted text (em-dash `—` and en-dash `–` *are* preserved, as are `+ * / = < >`). This is inherent to the source (it is absent even from the raw positioned-text layer, `--items-json`), affects both `pdf2md` output and the rebuilt pages, and cannot be recovered from the text layer without OCR. It shows up two ways:
  - **Prose:** hyphenated compounds are joined without the hyphen — `self-testing` → `selftesting`, `object-oriented` → `objectoriented`, `read-only` → `readonly`, `step-by-step` → `stepbystep`.
  - **Code (correctness caveat):** subtraction and negative offsets lose their operator — e.g. `Math.max(perf.audience - 30, 0)` reads as `Math.max(perf.audience 30, 0)`, and `points[i-1]` reads as `points[i1]`. When reading code examples, mentally restore a `-` between two operands that have only a space and no other operator.
  - It was left as-is rather than machine-inserting `-` across 833 code blocks, which would risk introducing *wrong* operators (e.g. corrupting `return result`); an obviously missing operator is safer for a reader than a confidently wrong one.
- **Cosmetic:** occasional split-italic spacing in refactoring names (e.g., `*Extract* *Function (106)*`) is an emphasis artifact that still renders as the correct name; a handful of reconstructed pages fence one inline-code identifier together with a trailing prose clause.
- **Verified:** 12 chapter headings present and in order; all code fences balanced; 0 residual garbled table rows, reader captions, or underline tags.
